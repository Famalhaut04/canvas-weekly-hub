# 系统概述 · Canvas Weekly Hub v2.2

把 Canvas 课程里的作业、提交状态、新资料、公告和变化整理成学习看板。普通同学使用自己的网页；有 agent 经验的同学也可运行本地 Python 引擎。

## 系统怎么工作

```text
你的浏览器（输入令牌、发起刷新）
    ↓ HTTPS 请求，令牌通过请求头发送
你自己的 Cloudflare Worker（提供网页、转发查询，不持久保存凭证）
    ↓ Bearer 认证，只查询课程相关接口
学校 Canvas（返回课程数据）
    ↓ 经自己的 Worker 返回浏览器
浏览器（筛选近期内容、比较快照、显示看板）
    ↓
当前浏览器存储 + 离线 HTML / 日历 ICS / 历史 JSON 备份
```

首次部署到自己的 Cloudflare 账号，打开自己的网址，粘贴令牌并点击“连接并生成看板”。网页自动使用本站代理；默认学校是城大。日常点击顶栏“刷新课程”查询，不会在关闭浏览器后自动更新。

网页显示上次成功更新的设备本地时间；默认满 3 天仅提示是否刷新，可在基础版设置中调整整数天数或关闭。点击“暂不刷新”只收起本页提示，点击“刷新课程”才查询。页面恢复可见后重新判断时间，关闭页面不保证收到提醒。该功能为 v2.2 同版本更新，个人实例须部署更新代码；实际上线核验见 [发布记录](1002_手动刷新同版本发布记录_v1.md)。

网页程序在 Worker，课程数据、Token 和历史在当前浏览器；不是把个人看板数据托管到作者仓库。本地路线则由电脑上的 Python 直接查询学校，配置与产物保存在本地数据目录，不需要 Cloudflare、KV 或云端定时器。

两条路线都应先确认学校允许个人 API 使用；本项目手动令牌模式不能认定为学校批准的应用。程序只查询，不代表 Token 本身仅有读取权限。助手填写的到期日是选填提醒，学校生成页可能要求期限；“仅检查连接”验证身份，主按钮才验证课程 / 作业读取。

## 每个部分是什么功能

| 部分 | 职责 |
|---|---|
| Canvas | 提供课程、作业、提交状态、文件清单与公告 |
| 访问令牌 | 允许以你的身份查询；项目不提交作业、不修改课程 |
| 个人 Worker | 提供看板网页，转发查询并解决跨域；不接入作者服务器 |
| 浏览器处理 | 筛选过去 7 天新增或更新内容、未来 7 天截止任务，比较改期、评分与移除 |
| 本机存储 | 当前浏览器保存令牌、设置、课程历史与快照，最多保留 52 份历史记录；另存提醒选项与绑定当前配置的成功更新时间 |
| 离线与备份 | HTML 离线查看；ICS 导入日历；JSON 迁移历史，不含令牌、SendKey 或订阅密钥 |
| Python 引擎 | 直接访问 Canvas，生成 Markdown 周报、看板、ICS、离线 HTML，按需下载课件 |
| agent / 计划任务 | 按时启动本地引擎；agent 可以读取周报并汇报，运行时需要自己的电脑在线 |

## 看板各个区域

| 区域 | 查看什么 |
|---|---|
| 待办提醒 | 即将截止的任务、剩余时间、提交与评分状态 |
| 本周新任务 | 过去 7 天新布置或更新的任务 |
| 课程动态 | 每门课程的新资料、公告、改期、新评分与移除提示 |
| 历史 / 搜索 | 切换历史记录，跨周检索任务、资料与公告 |
| 顶栏刷新 / 日历 / 设置 | 手动查询最新数据、下载日历、管理令牌、更新提醒和历史备份 |

待办不是全部未提交清单：它合并未来 7×24 小时截止的任务，以及近期新增 / 更新且未来截止的任务，已提交项也可能出现。刷新间隔只影响提醒，不改变筛选范围；详情见 [验收报告](1002_手动刷新与更新提醒验收_v1.md)。

作业查询失败不会覆盖旧快照；课件或公告部分失败会提示。网页版只列出课件，不自动下载正文。本地引擎支持课件下载。

## v2.2 功能边界

**暂停云端日历订阅、微信推送以及 KV / Cron 配置入口。** 本版不需要这些服务，也不把凭证存进云端 KV。日历下载仍可用：导入后由日历 App 提醒，但不会自动同步新变化，应刷新看板后重新导入。

旧实例升级后，即使保留 Cron，程序也不会查询或推送。原浏览器保留订阅密钥时，可用“停用旧版云端订阅”清理旧 KV 配置与快照；没有密钥时，到自己的 Cloudflare 处理。旧 KV 不会自动清空，Canvas 令牌也不会自动撤销。

清理按钮需要原 Worker 仍绑定原 KV，确认成功后再解绑；只删除该密钥的 cfg: / snap:，不删除 Cron 或整个 KV。个人实例不会自动升级，其他旧实例也不会自动停用。

## 数据与隐私

- 数据经过自己的浏览器、自己的 Worker 和学校 Canvas，不经过作者服务器；Cloudflare 是托管商，会处理转发请求。
- 浏览器存储不是加密保险箱，只在可信设备和自己部署的网址使用。令牌属于账号凭证，不要公开。
- 不默认开启 Worker 请求日志；代理只开放课程查询，不跟随携带认证的重定向，课程响应不缓存。
- 星数展示会访问 GitHub 公共 API，不发送课程数据或 Canvas 令牌；无课程数据遥测。
- 离线看板、日历、JSON 备份含个人课程信息，不要公开上传。备份仅排除配置凭证，不代表匿名化。
- 本地 Python 的 GitHub 推送默认关闭；开启时文件会上传到所配置的仓库，应使用自己的私有仓库。
- 新旧网址的浏览器存储独立，需要手动备份、导入历史并重新填写令牌。清除本机数据不撤销学校令牌或旧云端配置。
- 不同设备或浏览器也不会自动同步。离线 HTML 是导出时快照，不自动抓取；本地引擎再次运行可以重新生成。
- 使用云端 agent 时，输入的凭证及其读取的课程内容可能进入模型服务商，属于另一条数据边界；不要把真实 Token 粘贴到聊天，也不能因此承诺全程只在本机。
