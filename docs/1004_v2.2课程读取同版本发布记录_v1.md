## 这次问题为什么出现

| 问题 | 已确认的事实 | 不能据此推断 | 本次处理 |
|---|---|---|---|
| 文件接口 JSON 403，`user not authorized` | Canvas 拒绝该课程文件列表的访问 | 具体是哪项课程 / 账号 / API 权限限制尚未核实；不能一律归因于 Token 过期、网络或 Cloudflare | 分类为权限拒绝；继续读取有权限的作业和公告；不无限重试或绕过权限 |
| HTML 防护页 / 其他 403 | 与明确 JSON 权限拒绝属于不同响应 | 仅凭 403 不能确认哪个边缘防护 / 学校策略导致拦截 | 防护页与原因未确认的拒绝分别提示，不显示 HTML / 脚本 |
| 公告 404 | 原课程公告路径与官方接口不一致 | 不能解释成所有课程都没有公告或 Token 已失效 | 改为全局 `/announcements`，逐课程传 context_codes 和统计日期 |
| 文件分页不完整 | 原实现依赖返回条数和固定 20 页；Worker 未提供 Link | 不能把停止抓取解释成没有课件，也不保证单纯加大页数能解决 | 根据 Link 和窗口覆盖判断；校验下一页地址；预算耗尽仍明确提示不完整 |
| 本地 FETCH_FAILED | 本机默认 HTTPS 证书初始化复现 ASN1 加载错误 | 该错误不是 HTTP 403；匿名 401 不能证明个人 Token 或课程权限有效 | 同组可信系统证书兼容加载，保留证书与主机名验证，分开报告 TLS 问题 |
| 已交作业显示未提交 | 代码将缺失 / 未知 submission 状态布尔化成 False；用户看到的是 10月2日快照 | 同一天无法确认抓取与提交先后；真实 CS5489 原因未实测 | 未知显示待核验，豁免与重交分开；提交后须主动刷新，不修改历史冒充成功 |

反馈来源：[Issue #5](https://github.com/Famalhaut04/canvas-weekly-hub/issues/5)。接口与分页依据见 [课程读取验收](1003_课程读取问题修复验收_v1.md)；本机证书证据见 [HTTPS 报告](1004_本地HTTPS证书兼容修复_v1.md)；提交状态证据见 [提交状态报告](1004_作业提交状态核对与修复_v1.md)。这些开发报告保留当时“未发布”的历史状态，当前发布结果以本记录为准。

## 如何获得这次更新

- [v2.2 公告与附件](https://github.com/Famalhaut04/canvas-weekly-hub/releases/tag/v2.2)：网页用户下载 **worker.js**；本地用户下载 **canvas-weekly-hub-v2.2-source.zip** 或更新 main。
