# Canvas Weekly Hub v2.2 · 从零部署与个人令牌测试指南

日期：2026-10-04。适用于当前本地 Issue #5 修复代码。真实学校账号与 Cloudflare 部署尚待用户自行测试，本指南不表示已完成个人部署。

| 新增文件 | 用途 |
|---|---|
| 本指南 | 从零配置本地 Python、Cloudflare 手动部署、首次查询、刷新、排错与更新 |

## 先选择一条路线

| 项目 | 升级版：本地 Python | 基础版：个人 Cloudflare Worker |
|---|---|---|
| 地址 | `http://localhost:8137/` | 自己 Worker 的 HTTPS 正式网址 |
| 填 Token 的地方 | 本地 `canvas_config.json` | 自己网页的设置窗口 |
| 查询路线 | 本机 Python → 学校 Canvas | 浏览器 → 自己的 Cloudflare → 学校 Canvas |
| 数据保存 | 本机文件 | 当前网址、当前浏览器的存储 |
| 运行条件 | 已有 Python 3.8+，电脑在线 | 已部署自己的 Worker，浏览器与网络可用 |
| 手机 | 手机的 localhost 是手机自身，不能用它访问电脑 | 可打开个人网址，但首次需自己填写 Token；历史不自动同步 |
| 刷新 | 页面按钮调用本机 Python；或手动运行引擎 | 页面按钮发起查询；默认三天提醒，可调或关闭 |

你已经有 Token，可以直接进入配置步骤。两条路线选择一条即可；各自的数据不会自动同步。本地看板没有 Token 设置窗口，不能把 Cloudflare 网页的填写步骤套用到 localhost。

Token 是账号凭证，程序只查询不代表令牌本身仅可读取。自己在本地文件或自己的网页填写，不把真实 Token 放进聊天、Worker 源码、截图或 Git 提交。使用云端 agent 时，它读取的凭证或课程内容可能进入模型服务商，需单独理解此边界。

## 路线一：升级版，本地 Python 从零配置

### 第一步：打开项目目录与 PowerShell

在资源管理器进入项目目录，在地址栏输入 `powershell` 并回车，或打开 PowerShell 后执行：

```powershell
Set-Location -LiteralPath 'D:\GitHub\Projects\canvas-weekly-hub'
```

下面使用这台电脑已有并已确认的 Python 3.8.20，完整路径是 `D:\DevTools\anaconda3\envs_dirs\agent-sec38\python.exe`。其他电脑换成自己的解释器路径。无需安装包，不要求 python 命令已加入 PATH。

```powershell
& 'D:\DevTools\anaconda3\envs_dirs\agent-sec38\python.exe' --version
```

本机应显示 `Python 3.8.20`。若找不到文件，先核对解释器路径再继续。

### 第二步：创建配置文件

执行以下命令，已有配置时不会被示例覆盖：

```powershell
if (-not (Test-Path -LiteralPath '.\canvas_config.json')) {
    Copy-Item -LiteralPath '.\config\canvas_config.example.json' -Destination '.\canvas_config.json'
}
notepad '.\canvas_config.json'
```

记事本打开的是项目根目录的 `canvas_config.json`，不要只修改 config 子目录的示例。默认路径为 `D:\GitHub\Projects\canvas-weekly-hub\canvas_config.json`；若自己已设置 `CANVAS_HUB_DATA_DIR`，配置与产物应在那个目录，需保持引擎与服务使用同一目录。

### 第三步：自己填写 Token 并保存

保留 JSON 的英文双引号。第一次测试建议关闭课件自动下载；`github.push_enabled` 保持 false。最小有效示例如下，Token 占位文字必须由你在本地替换：

```json
{
  "canvas_url": "https://canvas.cityu.edu.hk",
  "access_token": "在本地替换为自己的真实Token",
  "lookback_days": 7,
  "upcoming_days": 7,
  "tz_offset_hours": 8,
  "term_filter": "",
  "token_expires_at": "",
  "token_remind_days": 5,
  "download_files": false,
  "download_dir": "downloads",
  "github": {
    "username": "",
    "repo_name": "learning-hub",
    "repo_dir": "",
    "push_enabled": false
  }
}
```

自己粘贴完整 Token，不带多余空格或换行；按 Ctrl+S 保存。不要把文件保存成 `canvas_config.json.txt`。`token_expires_at` 可留空，也可填学校令牌的实际到期日 YYYY-MM-DD，它只是提醒信息。

`download_files=false` 仍会查询文件列表并显示新资料，只暂停下载文件正文。首次数据读取正常后，如有需要再改为 true。

### 第四步：只检查配置格式

```powershell
& 'D:\DevTools\anaconda3\envs_dirs\agent-sec38\python.exe' -B '.\canvas_weekly_report.py' --check-config
```

通过时会看到 `CONFIG_OK`，以及云端备份关闭的说明。它不请求学校，不能证明 Token 有效。出现 CONFIG_MISSING / CONFIG_INVALID 时先按提示修正文件名、JSON 或配置字段，不进入抓取。

### 第五步：首次读取真实课程

```powershell
& 'D:\DevTools\anaconda3\envs_dirs\agent-sec38\python.exe' -B '.\canvas_weekly_report.py'
```

等待命令结束，再看实际输出：

| 输出 | 意义 |
|---|---|
| `OK` | 主查询与可选列表完成，生成当前数据和看板；具体课程数以实际输出为准 |
| `PARTIAL_OK` | 课程、作业可用，但文件 / 公告有部分未更新；看分类警告与课程说明 |
| `FETCH_FAILED` | 关键查询失败，本次不替换整份旧看板与作业快照 |
| `CONFIG_MISSING` / `CONFIG_INVALID` | 配置未就绪，先修正后再运行 |

默认产物位于项目目录：`data.json`、`last_state.json`、`deadlines.ics`、`我的学习网站.html`，日期周报与离线 HTML 在 reports 子目录。若用自定义数据目录，以命令打印的路径为准。

磁盘故障等输出阶段失败仍需检查实际产物，Python 多文件写入没有整体原子事务保证。首轮失败时没有旧看板可显示，不能把空页面算成配置成功。

### 第六步：打开看板

服务尚未启动时运行：

```powershell
& 'D:\DevTools\anaconda3\envs_dirs\agent-sec38\python.exe' -B '.\serve_board.py'
```

看到启动提示后，浏览器打开 `http://localhost:8137/`。保持这个 PowerShell 窗口运行；Ctrl+C 停止服务，关闭终端后网址不能继续使用。已有服务且页面正常时，先运行引擎、再 Ctrl+F5 重载即可，不重复启动同一端口。

也可以双击生成的“我的学习网站.html”，那是抓取时的离线快照，不会自动连接学校。它与本地服务网页的更新方式不同。

### 第七步：后续刷新与重启

服务在线时点击网页顶部“刷新课程”，会运行本机引擎，并按结果更新网页；不要同时在终端另跑一份抓取。也可以手动运行第五步命令，再重载页面。

关机或关闭终端后，下次只需重新启动第六步的服务；要获取新课程数据再点击刷新。修改 Token 或下载选项时编辑同一个配置文件，先检查配置再运行。

当前本地路线没有网页“三天提醒”设置，也没有自动创建计划任务。若想每三天查询，需要另行配置自己已有的 agent / 系统计划任务，电脑、环境与网络要在线。`lookback_days=7` 是数据回溯窗口，不是每七天自动运行。

## 路线二：基础版，Cloudflare 从零部署

### 第一步：准备自己的账号与完整代码

准备可登录的 Cloudflare 账号并完成控制台要求的验证。本轮采用手动编辑器路线，需要自己的账号和浏览器，无需本地 Node / Wrangler、GitHub 仓库授权或额外 Python 包。

用文本编辑器打开 `D:\GitHub\Projects\canvas-weekly-hub\worker.js`。按 Ctrl+A、Ctrl+C，复制全文。文件开头有“自动生成”，包含 `const HUB_PAGES` 和后面的 Worker 运行逻辑。不要把 Token 填入这个文件。

### 第二步：创建新的个人 Worker

1. 打开 [Cloudflare 控制台](https://dash.cloudflare.com/)，登录自己的账号。
2. 进入 Workers & Pages。
3. 点击 Create application / Create。
4. 选择 Hello World 模板；界面也可能显示 Start with Hello World。
5. 给 Worker 起名，例如 `my-canvas-hub`，点击 Deploy，等待创建完成。
6. 打开该 Worker，点击 Edit code。

这些按钮依据 [Cloudflare 官方控制台流程](https://developers.cloudflare.com/workers/versions-and-deployments/gradual-deployments/#via-the-cloudflare-dashboard)。账户界面可能不同；官方一般入口也包含 Git 导入等选项。若找不到模板，保留当前页面并核对 [控制台指南](https://developers.cloudflare.com/workers/get-started/dashboard/)，不要误改为导入作者尚未更新的仓库。此步骤未用真实 Cloudflare 账号走通。

已有个人 Worker 想保留原网址与浏览器历史时，直接打开原 Worker 的 Edit code，进入下一步；创建新 Worker 会形成新网址和新的浏览器存储。

### 第三步：替换代码并部署到生产

1. 点击代码编辑区域，使光标进入文件内容。
2. 在该区域 Ctrl+A 全选 Hello World，Ctrl+V 粘贴当前本地完整 worker.js。
3. 检查文件开头、`const HUB_PAGES` 及文件末尾均已复制完整。
4. 点击 Deploy，等待生产部署成功提示。

保存新版本与生产部署不同，编辑器预览成功也不等于正式网址已更新。选择实际 Deploy；如果有流量分配配置，确认新的版本承担全部生产流量。项目无需填写 Canvas Token 环境变量、KV、Cron、SendKey 或学校数据文件。

### 第四步：打开自己的正式网址

回到 Worker 概览或 Settings → Domains & Routes，找到自己的 `workers.dev` 地址，通常是：

```text
https://my-canvas-hub.你的账号子域名.workers.dev/
```

这是格式示意，直接使用控制台提供的网址，不照搬“你的账号子域名”。默认域名规则与设置入口见 [官方 workers.dev 说明](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)。

新标签页打开、收藏这个正式网址。不要收藏带额外版本前缀的版本网址或编辑器预览，它们用于特定版本测试；区别见 [官方 Version URLs 说明](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/)。

部署成功的标志是自己的网页显示“连接你的 Canvas · v2.2”，有 Token 输入框并自动使用本站代理。不应仍显示 Hello World、JSON 健康信息或作者的公共部署引导页。

### 第五步：填写个人 Token

1. 在自己的正式网址选择“基础版”；首次页面通常已展开。
2. 在 Canvas Token 输入框中粘贴自己的 Token。
3. 默认学校地址为 `https://canvas.cityu.edu.hk`。其他学校展开地址选项，填写自己的 Canvas HTTPS 站点地址。
4. 到期日选填，可按学校实际期限填写；它不会改变学校令牌的有效期。
5. 点击“连接并生成看板”，等待身份与课程查询结束。

只有“仅检查连接”通过还不够：它仅检查 Worker 和用户身份，不验证课程、作业、公告和文件的全部读取。

已经有有效 Token 时直接填写；需要重新获取时，自己登录学校 Canvas → Account / 账户 → Settings / 设置 → New Access Token / 新访问令牌，按学校要求生成并立即复制，返回自己的助手。学校具体期限和界面以实际为准，不把 Token 发进聊天。

### 第六步：确认读取状态与设置提醒

确认课程名称、作业与截止信息。若部分成功，查看文件 / 公告成功门数并展开受影响课程；旧内容必须标注上次成功时间，失败空结果不能解释为没有资料。

日常点击顶部“刷新课程”才查询。设置 → 基础版 → 更新提醒，可保留默认三天，或修改整数天数 / 关闭，再点击“保存提醒设置”。到期只提示，不会自动读取；关闭页面后不会后台查询。提醒时间在部分成功时指作业成功更新，各文件 / 公告卡片的时间才代表各自读取成功。

手机打开同一正式网址时仍使用手机浏览器自己的存储，需自己填写 Token。电脑历史不自动出现在手机上；迁移历史先备份、再导入，导入会替换目标浏览器历史，操作前保留副本。

## 真实测试时怎么判断

| 情况 | 看到什么 | 下一步 |
|---|---|---|
| Worker 网址打不开 | 浏览器无法打开页面 | 核对正式网址、部署状态、workers.dev 是否启用及网络可达性；还没到 Token 验证步骤 |
| 仍是 Hello World | 默认示例文字 | 核对是否替换了正确 Worker 的代码并执行 Deploy |
| 需要填写 Worker 代理地址 | 可能是公共入口或旧代码 | 确认打开自己部署的正式网址，使用完整本地修复包 |
| 401 / 认证失败 | 身份或课程请求失败 | 在本地 / 自己网页核对完整令牌、学校地址与期限；需要时在学校更换 |
| JSON 明确权限 403 | 某课程文件 / 公告不可访问 | 到该课程学校页面核对权限；不反复换令牌，不绕过限制 |
| HTML 防护 / 未确认的 403 | 分类提示访问限制 | 核对学校访问限制与实际错误类别，不能仅凭状态码确定原因 |
| 公告仍 404 | 公告未读取，但作业可能正常 | 确认使用本次修复包；若已更新，记录脱敏课程名与类别，学校支持待核验 |
| 结果不完整 | 分页预算、循环、日期或地址异常 | 已读内容不代表全部，在 Canvas 查看完整资料；记录课程和分页类别 |
| 本地 8137 端口占用 | 启动报地址已使用 | 使用现有服务；确需重启时在它原终端 Ctrl+C 停止，再运行一次服务 |
| 本地服务打开但没有新数据 | 加载失败或旧看板 | 确认首次引擎已生成数据、输出目录与服务一致，再 Ctrl+F5 |
| Python 报证书错误 | 请求未完成 | 当前引擎已兼容本机 Windows 批量 DER 加载的 ASN1 错误；使用当前修复代码重新运行。仍失败时按证书加载、验证或握手类别排查，保留 TLS 校验，见 [证书修复记录](1004_本地HTTPS证书兼容修复_v1.md) |
| 浏览器不能保存 | 存储被禁用 / 空间不足 | 允许本站存储或换可信浏览器；存储失败不能算刷新成功 |

学校文件 403 的具体原因仍未实测。新代码提供准确分类与失败保护，不承诺能读取学校拒绝的内容。Issue #4 的待办漏同步保持独立，不将本次读取修复当作它已解决。

可以进行一次首次抓取，再进行一次同日刷新，核对旧数据保留与状态。反馈只需脱敏课程名、错误类别和发生时间；截图遮住 Token、认证头、个人身份及不打算公开的课程内容。

## 后续升级与数据保存

本地源码更新后，先保留个人配置和产物，重启服务、再抓取；不覆盖本次尚未发布的修改。修改源码需要重新生成部署包时，用已有 Python 执行 `web/build_web.py`，它不读取学校 Token。

Worker 升级时先备份浏览器历史，再用新完整 worker.js 替换原 Worker 并 Deploy；保持原网址能继续使用该浏览器已有存储。换网址、设备或浏览器需要备份迁移和重新填写 Token。学校令牌更换后在对应路线替换，不在代码里写死。

当前两条路线不默认设置 KV、云端定时器或微信推送。旧实例以前配置过的 KV 不会自动清空，其他旧 Worker 不会随本次新建实例停用；按已有 [升级教程](Cloudflare部署图文教程.md#旧用户升级迁移及停用提醒)处理自己的资源，本指南不执行清理。

本地配置文件含凭证，本地课件 / 周报与离线 HTML 含课程隐私；网页课程历史在当前浏览器，查询经过自己的 Cloudflare 和学校，不经过作者服务器或作者仓库。导出备份排除配置凭证不等于课程匿名化；清除浏览器也不等于撤销学校 Token。

本次仅核对并编写流程，确认已有 Python 可用；未创建个人配置、未读写真实 Token、未请求个人课程、未安装依赖、未变更云端资源或发布代码。
