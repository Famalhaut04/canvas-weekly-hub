# 工作原理 · 这个程序是怎么运行的

> 这份文档回答三个问题：**数据从哪来、经过哪里、存在哪**。
> 前半部分用大白话+示意图（不看代码也能懂）；后半部分是给技术同学的准确细节。

---

## 一、30 秒版本

```
你的 Canvas 账号（城大服务器，存着作业/课件/成绩）
        │  ① 用你的「访问令牌」去问它
        ▼
小助手（转发器）──── ② 把拿回的数据交给「引擎」
        │
        ▼
引擎（处理程序）──── ③ 生成三样东西：
        ├── 📋 周报（本周新作业/未提交/新课件/变化）
        ├── 🌐 看板网站（可交互网页，含历史归档）
        └── 📅 日历文件（截止时间 → 手机提醒）
```

**核心一句话**：程序定期拿着你的令牌去城大 Canvas「抄」一遍你的课程数据，整理成好看好用的看板和提醒。它**只读不写**——永远不会替你交作业、改成绩。

---

## 二、数据从哪来：Canvas 开放接口 + 你的令牌

### 令牌是什么？

城大 Canvas 给每个学生提供「访问令牌」（一串字符），相当于**一把只属于你的备用钥匙**：
- 在 Canvas 网页上生成（账户 → 设置 → + 新访问令牌）
- 拿着它，程序就能以你的身份**查询**你的课程数据（作业列表、提交状态、文件清单、公告）
- 它只有读权限的用法，不能改你的任何东西
- 城大规定它最长活 90 天，到期重新生成一把即可

### 程序具体问了 Canvas 什么？

| 接口 | 拿到什么 | 用来做什么 |
|---|---|---|
| `/courses` | 你本学期的课程列表 | 看板里的课程卡片 |
| `/courses/:id/assignments`（含 submission） | 每门课全部作业 + **你的提交状态**（未提交/已提交/已评分） | 待办排序、未提交红标、新评分检测 |
| `/courses/:id/files` | 每门课的文件清单（PPT/PDF 名字、大小、上传时间） | 「本周新资料」列表 + 自动下载 |
| `/courses/:id/announcements` | 老师发的公告 | 公告区 |

## 三、为什么需要一个「小助手」（Worker）？

### 问题：浏览器的安全限制

城大 Canvas 没有开放「跨域访问」（CORS）——我们实测过：浏览器里的网页**直接**去请求 Canvas 接口，响应会被浏览器安全机制拦截（这也是大多数学校 Canvas 的默认姿态）。

### 解决：你自己的转发器

「小助手」是一段约 240 行的开源代码，部署在 **你自己的 Cloudflare 免费账号**里。浏览器把请求发给它，它替你转给 Canvas，再把结果带回来：

```
浏览器（你的看板页面）──请求──▶ 你的 Worker ──转发──▶ canvas.cityu.edu.hk
浏览器 ◀──数据（加了跨域许可头）── 你的 Worker ◀──数据── Canvas
```

**它为什么可信**：
- 代码 100% 开源（仓库里的 `worker.js`），只做"转发"一件事，任何人可审查
- 令牌通过请求头**逐次传递**，代理模式下不落任何存储
- 部署在你自己的账号里——连本项目作者都碰不到

> 用命令行引擎（Python）的同学**不需要** Worker：Python 程序直接访问 Canvas 不受浏览器跨域限制。

## 四、引擎：数据怎么变成看板

引擎（`canvas_weekly_report.py`，约 700 行纯标准库 Python）每次运行做 6 件事：

1. **抓取**：带令牌调上面 4 个接口，拉全部活跃课程
2. **算增量**：和上次的「快照」（`last_state.json`）对比——
   - 截止时间变了 → 「改期：9/29 → 10/6」
   - 提交状态变成已评分 → 「新评分」
   - 上次有、这次没有 → 「已删除/隐藏」
3. **生成周报**：`reports/canvas周报_日期.md`
4. **生成看板数据**：`data.json`（结构化数据，按周累积，最多 52 周）
5. **渲染看板**：把数据和网页模板合成——
   - 服务器模式：`data.json` + `index.html` 由本地小服务（`serve_board.py`）托管，页面里 🔄 按钮再调引擎刷新
   - 离线模式：数据直接内嵌进单个 HTML 文件（`我的学习网站.html`），双击就能开
6. **下载课件 + 日历 + 备份**：新 PPT/PDF 按课程存到 `downloads/`；截止时间写成 `deadlines.ics`；数据推送到你的私有 GitHub 仓库留底

网页版（无 Python 环境）的同学：第 1~2 步在浏览器里完成（经你的 Worker），第 4~5 步存浏览器 localStorage——同样的逻辑，不同的执行位置。

## 五、提醒是怎么到你手上的

| 提醒方式 | 原理 | 何时生效 |
|---|---|---|
| 📅 手机日历 | 引擎/页面生成 **ICS 订阅链接**；日历 App 定期来拉取最新截止时间 | 订阅一次永久自动更新，截止前 2 小时系统级提醒（**最可靠**） |
| 💬 微信推送 | 你的 Worker 里有个**定时器**（每天 18:30 自动醒来）→ 拉一遍 Canvas → 有未提交/变化时调 Server酱 推到你微信 | 需填自己的 SendKey；关电脑也照推（跑在 Cloudflare 上） |
| 🤖 agent 汇报 | ZCode 定时任务每周五 19:00 跑引擎，读完周报用中文汇报给你 | 需电脑开机 |
| 🖥 页面内提示 | 打开着看板时的浏览器通知与红标 | 仅页面打开时 |

## 六、隐私模型：什么数据、在哪、谁能看

| 数据 | 存在哪 | 谁能接触 |
|---|---|---|
| Canvas 令牌 | ① 你本机的 `canvas_config.json`；② （仅订阅用户）你自己 Cloudflare 的 KV 存储 | 只有你 |
| 课程数据 | 你本机文件 / 你浏览器 localStorage / 你的私有 GitHub 仓库 | 只有你 |
| 看板网页 | 你本机（localhost）或离线单文件 | 只有你（发给别人别人才看得到） |
| 网页版工具本身 | 公开 GitHub Pages（只有代码，无任何人的数据） | 所有人（这就是开源的部分） |

**本项目没有中心服务器**：作者不收集令牌、不接触任何人的课程数据；「公共工具」和「私人数据」彻底分离。

## 七、给技术同学的实现细节

- **引擎**：Python 3.10+，零第三方依赖（urllib/http.server/json），Win/Mac/Linux 通用；数据目录可经 `CANVAS_HUB_DATA_DIR` 重定向
- **看板**：单文件 HTML+原生 JS，无构建链；同一模板三种运行形态（服务器 data.json / 内联 `__HUB_DATA__` / localStorage），深浅色经 CSS 变量与 `prefers-color-scheme`
- **Worker**：ES Module，`/proxy/*` 无状态转发（CORS: *，令牌走 `X-Canvas-Token` 头），`/setup`+`/ics` 走 KV（按 secret 索引），`scheduled()` Cron 做日推；请求带浏览器 UA 以降低被 Canvas 边缘防护误拦概率
- **变化检测**：作业快照 `{course_id: {assignment_id: {due_iso, workflow_state}}}` 全量对比
- **ICS**：手写 RFC5545 最小集（VCALENDAR/VEVENT/VALARM，-PT2H 触发），CRLF 行尾
- **分页**：Canvas API `per_page=100` + 翻页循环，上限 20 页

## 八、常见疑问

- **它会动我 Canvas 里的东西吗？** 不会。全程只用只读查询接口，不提交、不修改、不删除。
- **断网/关机会怎样？** 定时任务当次不跑（不补跑），下次到点恢复；已生成的看板和离线文件不受影响。
- **令牌泄露了怎么办？** 到 Canvas 设置页删除该令牌立即失效；再生成新的填回去即可。
- **为什么数据 sometimes 显示慢几秒？** 抓取要逐门课调接口（10 门课约 10~25 秒），属正常。
