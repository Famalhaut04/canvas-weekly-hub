# Canvas Weekly Hub · 从零部署指南

> 本文档带你从零搭建一套**全自动课程动态监控系统**：定时抓取你在 Canvas 上的全部课程，汇总每门课的新作业、即将截止的任务、新上传的 PPT/资料和公告，生成中文周报保存到本地，同时自动更新你的个人学习网站（GitHub Pages），并可通过 ZCode 自动化任务每周向你汇报。
>
> 适用于**任何使用 Canvas LMS 的学校**。本文以香港城市大学（`https://canvas.cityu.edu.hk`）为例，其他学校只需把配置里的 `canvas_url` 换成自己学校的 Canvas 地址。
>
> 预计耗时：30～40 分钟（大部分时间在等 GitHub Pages 生效）。全程免费。

## 1. 这套系统是什么

```
┌─────────────┐   定时（如每周五 19:00） ┌──────────────────────────┐
│  ZCode 定时  │ ─────────────────────▶ │ canvas_weekly_report.py   │
│  自动化任务   │                        │ （本仓库根目录）             │
└─────────────┘                        └────────────┬─────────────┘
                                                    │ 调用 Canvas REST API
                                                    │（用你自己的 Token，只存本地）
                                                    ▼
                                        ┌───────────────────────┐
                                        │   你的 Canvas 账号数据   │
                                        │ 作业/文件/公告/课程       │
                                        └───────────┬───────────┘
                                                    │
                              ┌─────────────────────┼─────────────────────┐
                              ▼                     ▼                     ▼
                    reports/canvas周报_日期.md   网站仓库 data.json      终端输出摘要
                    （本地 markdown 周报）        （git push 到 GitHub）  （AI 任务整理后汇报）
                                                    │
                                                    ▼
                                        https://你的用户名.github.io/仓库名/
```

**每次运行产出三样东西：**

| 产出 | 形式 | 用途 |
|---|---|---|
| 课程动态周报 | markdown 文件（本地 `reports/`） | 存档复习，含每课新任务/新资料/公告明细 |
| 学习网站更新 | GitHub Pages 页面 | 待办倒计时、新资料卡片、跨周搜索、历史归档 |
| 中文汇报 | ZCode 任务输出 | 定时直接告诉你本周要做什么 |

## 2. 准备工作

### 必装软件（Windows 为例，Mac/Linux 同理，路径自行调整）

| 软件 | 用途 | 检查命令 | 安装方式 |
|---|---|---|---|
| Python 3.10+ | 运行周报脚本 | `python --version` | https://www.python.org/downloads/ （勾选 Add to PATH） |
| Git | 版本管理与推送 | `git --version` | https://git-scm.com/download/win |
| GitHub CLI (gh) | 创建仓库 / 开通 Pages / 认证 | `gh --version` | https://cli.github.com/ 或 `winget install GitHub.cli` |
| ZCode（可选） | 承载定时自动化任务与中文汇报 | — | 见第 7 步；不用它也可用任务计划程序替代 |

装好后先完成 GitHub 登录：

```bash
gh auth login
# 按提示选择：GitHub.com → HTTPS → 用浏览器登录
gh auth status   # 确认显示 Logged in
```

### 你需要有的账号

- 学校 Canvas 账号（能在浏览器正常打开你学校的 Canvas 即可）
- GitHub 账号（没有就在 https://github.com/signup 注册一个）

## 3. 第一步：获取项目文件

**克隆本仓库作为工作目录**（后续所有操作都在这个目录里进行）：

```bash
git clone https://github.com/Famalhaut04/canvas-weekly-hub.git canvas-weekly-hub
cd canvas-weekly-hub
```

> 也可以在 GitHub 页面点绿色 `Code` → `Download ZIP` 下载解压，效果相同。

目录结构：

```
canvas-weekly-hub\                ← 你的工作目录
├── canvas_weekly_report.py       # 周报脚本
├── site-template\
│   └── index.html                # 学习网站首页模板
├── config\
│   ├── canvas_config.example.json  # 配置模板（Token 留空）
│   └── data.template.json          # 网站初始空数据
├── docs\                         # 本文档与截图
├── reports\                      # （运行后自动生成）每周周报
└── site-repo\                    # （第 5 步创建）你的网站仓库
```

## 4. 第二步：获取你自己的 Canvas API Token

> 🔐 **本仓库出于安全考虑不包含任何人的凭证。** Token 需要每个使用者自己生成、自己填写、自己保管。

1. 浏览器登录你学校的 Canvas（示例：https://canvas.cityu.edu.hk）
2. 左侧边栏最下方点 **账户(Account) → 设置(Settings)**
3. 页面拉到最底部，找到 **已批准的集成（Approved Integrations）**，点 **+ 新访问令牌（+ New Access Token）**
4. 弹窗里：
   - **目的**：填一个好认的名字，如 `weekly-report`（只是备注标签）
   - **截止日期**：部分学校限制最长 90 天（如 CityU），保持默认即可
5. 点 **生成令牌**，**立刻复制**弹出的令牌字符串（只显示这一次！）
6. 复制配置模板并填入令牌：

```bash
cp config/canvas_config.example.json canvas_config.json
# 用任意编辑器打开 canvas_config.json，把令牌粘贴进 "access_token": "" 的引号中间，保存
```

> ✅ **放心填**：`canvas_config.json` 已被本仓库的 `.gitignore` 排除，`git status` 里永远看不到它，不会被提交到任何仓库。若某天 `git status` 意外显示了它，停下来检查 `.gitignore`。

> ⚠️ Token 等同于你的 Canvas 账号凭证，**不要发给任何人、不要上传到任何仓库、不要截图**。怀疑泄露时，回到 Canvas 设置页删除该令牌即可立即失效。

## 5. 第三步：创建你的 GitHub 网站仓库

以下命令在 **Git Bash** 中执行（装 Git 自带；Mac 直接用终端）。把路径和用户名替换成你自己的。

```bash
# 在工作目录里建网站仓库
mkdir -p site-repo/learning-hub
cd site-repo/learning-hub

# 放入网站初始文件：页面模板 + 空数据文件
cp ../../site-template/index.html .
cp ../../config/data.template.json data.json

# 初始化本地仓库
git init -b main
git add -A
```

**⚠️ 关键一步（跳过大概率推送失败）**：GitHub 默认开启"邮箱隐私保护"，会拒绝包含真实邮箱的提交（报错 GH007）。先拿到你的 GitHub 数字 ID，配置官方 noreply 邮箱：

```bash
gh api user --jq .id                     # 记下输出的数字，比如 12345678
git config user.name  "你的GitHub用户名"
git config user.email "12345678+你的GitHub用户名@users.noreply.github.com"   # 数字换成上一步的
git commit -m "初始化学习网站"
```

创建远程仓库并推送，然后开通 GitHub Pages：

```bash
gh repo create learning-hub --public --source . --push
gh api -X POST repos/你的GitHub用户名/learning-hub/pages -f "source[branch]=main" -f "source[path]=/"
```

等 1～2 分钟，浏览器打开 **https://你的用户名小写.github.io/learning-hub/** ，看到页面显示"暂无数据"即成功。

> 说明：GitHub 免费账号的 Pages 需要**公开仓库**。仓库里只有页面代码和课程任务摘要数据（`data.json`），不含你的 Token。若介意课程数据公开，有两个选择：
> ① 升级 GitHub Pro 后把仓库设为 Private（Pages 仍可发布，但**页面 URL 本身仍是公开可访问的**，只是仓库源码看不到了）；
> ② **完全私密的本地看板（免费）**：把仓库设为 Private（免费版 Pages 会随之停用），改为本地查看——在网站仓库目录运行 `python -m http.server 8137`，浏览器打开 `http://localhost:8137/` 即可（手机在同一 WiFi 下也能访问）。周报脚本与数据更新完全不受影响，`git push` 照常作为云端备份。

## 6. 第四步：配置并首次运行

### 填写 `canvas_config.json`（在第 4 步已复制好）

| 字段 | 说明 |
|---|---|
| `canvas_url` | 你学校 Canvas 地址，如 `https://canvas.cityu.edu.hk` |
| `access_token` | 第 4 步你自己生成的令牌 |
| `lookback_days` | 每次统计"过去几天"的新内容，默认 7 |
| `upcoming_days` | 每次统计"未来几天"要截止的作业，默认 7 |
| `tz_offset_hours` | 展示时区，默认 8（UTC+8），其他地区自行调整 |
| `term_filter` | 只统计特定学期就填学期名关键字，留空 = 全部活跃课程 |
| `github.username` | 你的 GitHub 用户名 |
| `github.repo_name` | 第 5 步创建的仓库名（示例 `learning-hub`） |
| `github.repo_dir` | 本机网站仓库**绝对路径**（正斜杠），如 `D:/canvas-weekly-hub/site-repo/learning-hub` |
| `github.push_enabled` | 保持 `true`（每次运行自动 commit + push 网站数据） |

### 跑一次验证（在工作目录根下）

```bash
python canvas_weekly_report.py
```

**成功的输出长这样**（数字取决于你的账号）：

```
OK 课程数=10 新作业=4 即将截止=1 新资料=8 新公告=0
报告文件：D:\canvas-weekly-hub\reports\canvas周报_2026-09-17.md
网站状态：网站已更新并推送
网站地址：https://xxx.github.io/learning-hub/
```

此时打开你的网站，应该已经能看到第一份真实周报了。报错请对照[第 9 节常见问题](#9-常见问题排查)。

## 7. 第五步：创建每周自动化的汇报任务

在 **ZCode** 对话里说"帮我创建一个自动化任务"，或直接使用以下参数：

- **执行时间**：每周五 19:00（cron 表达式 `0 19 * * 5`，重复执行）
- **任务标题**：`每周五晚7点Canvas课程周报并更新学习网站`
- **任务内容（prompt）**：把下面模板整段粘贴，**只替换尖括号里的路径/地址**：

```text
执行 Canvas 每周课程动态汇报任务（每周五晚7点周报）。

1. 运行周报脚本：python "<你的工作目录>\canvas_weekly_report.py"
   脚本会读取同目录 canvas_config.json 中的 Canvas access_token，调用 Canvas REST API 抓取
   本学期全部活跃课程过去7天的新作业/任务（含老师有更新的）、未来7天即将截止的作业、
   新上传的 PPT/PDF 等资料、新公告，然后：
   - 在 "<你的工作目录>\reports\" 下生成当天的 markdown 周报（文件名含日期）；
   - 自动把本周数据合并进学习网站仓库 "<你的工作目录>\site-repo\learning-hub" 的 data.json
     并 git push，线上网站 https://<你的用户名小写>.github.io/learning-hub/ 随之更新。

2. 脚本成功结束后，读取 reports 目录下本次生成的最新周报文件，用中文向用户完整汇报：
   - 先给本周要点摘要：本学期课程数、各门课新作业数量、新资料数量、最近一次作业截止时间；
   - 再逐门课程列出：① 本周新布置/有更新的作业（名称、截止时间、分值、状态）；
     ② 未来7天即将截止的作业；③ 新上传的 PPT 和资料（文件名、类型、上传时间）；
     ④ 重要公告（标题+摘要）；
   - 最后注明：完整周报文件路径、学习网站链接、提醒用户按截止时间安排复习。

3. 异常处理（务必遵守，不要编造数据）：
   - 若脚本报 CONFIG_MISSING（access_token 为空）或 FETCH_FAILED（认证失败/网络不通），
     直接如实告诉用户本次未能获取 Canvas 数据，并指引用户检查 token 或网络后重试；
   - 若 git push 失败，说明网站未能更新，但周报文件仍已生成，照常汇报周报内容并说明原因；
   - 不得虚构任何课程、作业、文件内容；报告中只呈现脚本实际抓到的数据。
```

创建完成后让 ZCode 列出任务确认 `nextRunAt` 是下一个周五 19:00。

**注意事项：**

- 定时运行时电脑需开机、ZCode 可运行（错过当次不会补跑）；
- 不用 ZCode 也可以：用 Windows 任务计划程序（Task Scheduler）定时执行 `python canvas_weekly_report.py`，只是没有"读周报并用中文汇报"这一步；
- 想临时手动跑一次，随时执行那条 python 命令即可，效果完全相同。

## 8. 日常维护

| 事项 | 频率 | 怎么做 |
|---|---|---|
| **更换 Token** | 到期时（部分学校限制 90 天） | Canvas 设置页删旧令牌 → 生成新令牌 → 替换 `canvas_config.json`。到期后自动化会明确报认证失败，不会静默出错。建议设个日历提醒 |
| 新学期开始 | 每学期 | 无需操作；若想只看新学期课程，把 `term_filter` 改成新学期名关键字 |
| 改网站界面 | 想改就改 | 编辑 `site-template\index.html` → 跑一次脚本，会自动同步到网站仓库并推送 |
| 更新本项目 | 随意 | `git pull` 拉取本仓库更新（你的 `canvas_config.json`、`reports\`、`site-repo\` 不会被覆盖，它们不在版本控制内） |

## 9. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 输出 `CONFIG_MISSING` | `access_token` 没填 | 打开 `canvas_config.json` 填入**你自己**的令牌 |
| `Canvas API ... HTTP 401` | 令牌错误或已过期 | 重新生成令牌并替换；确认没有多余空格/换行 |
| `无法连接 Canvas` | 网络/防火墙问题 | 换网络重试；确认浏览器能打开你学校的 Canvas |
| 推送报 **GH007**（push declined due to email privacy） | 提交用了真实邮箱 | 按第 5 步方法配置 noreply 邮箱后重新 commit + push |
| 推送要求登录 / push 失败 | Git 凭据未配置 | 运行 `gh auth setup-git` 后重试 |
| 课程列表为空 / 少课 | `term_filter` 填了不匹配的关键字 | 清空 `term_filter` 或改对关键字 |
| 网站没变化 | GitHub Pages CDN 缓存（几分钟） | 等几分钟强刷（Ctrl+F5）；`git log` 确认推送成功 |
| 直接双击 index.html 看不到数据 | 浏览器限制本地文件 fetch | 属正常。通过 GitHub Pages 访问，或本地 `python -m http.server` 后用 localhost 打开 |
| 资料卡片点不开文件 | Canvas 文件没有公开直链 | 属正常。卡片跳转到课程「文件」页，浏览器登录 Canvas 后即可下载 |
| **不小心把 Token 提交进了仓库** | 忘了用模板复制、或改了 .gitignore | **立即**去 Canvas 吊销该令牌 → 清理提交历史（或删除仓库重建）→ 重新按第 4 步配置 |

## 10. 安全须知

- **Token 只存本机** `canvas_config.json`（被 `.gitignore` 排除），绝不入库、不发人。
- Canvas API Token 默认仅能**读取**你的 Canvas 数据，不能替你提交作业，但仍等同于敏感凭证，妥善保管。
- 学习网站仓库（公开）只包含：页面代码 + 课程任务摘要数据（作业名/截止时间/文件名等）。**不含 Token、不含作业正文**。
- 完整下线：删除 ZCode 自动化任务 + 删除 GitHub 网站仓库 + 删除本目录即可。
