## 结果与配置变化

本轮完成 A 路线：保留 GitHub Pages + 自有 Worker 的网页模式及本地 JSON 模式，不需要迁移现有浏览器字段或重建部署架构。

| 使用场景 | 升级后的行为 |
|---|---|
| 输入配置并测试 | 校验完整 HTTPS 站点、令牌、日期；认证成功才保存，失败保留原配置 |
| 直接抓取 | 先检查 Worker，再按课程显示进度；成功时配置、看板、快照一起保存 |
| 作业读取失败 | 中止本次抓取，保留旧快照，避免把网络失败报告成“作业已移除” |
| 课件 / 公告部分失败 | 仍可生成看板，但显示警告，并记入周报数据；本地 Markdown 也提示 |
| 存储失败 | 不再静默成功；相关数据写入失败时尝试恢复旧值 |
| 启用订阅 | 新 Worker 提前告知是否绑定 KV；旧 Worker 提示无法预检；无 KV 可继续看板与日历下载 |
| 只在本地使用 | 示例只需填写 Canvas 地址与令牌，默认不推送；先跑 `--check-config`，再抓取和启动本地看板 |
| 390px 窄屏 | 设置窗口与关闭按钮位于屏幕内；长地址、标题允许换行 |

唯一默认值变化是**新示例配置的** `github.push_enabled` 从 `true` 改为 `false`，仓库路径与用户名留空。用户现有配置文件没有改写；已有 `true` 配置仍保留其推送行为。新增字段校验会拒绝过去被静默接受的非法日期、字符串数字、错误布尔类型和无效仓库路径。

本地看板服务现在读取引擎维护的本地 `data.json` 和仓库页面模板，不依赖云端网站目录；它仅监听 `127.0.0.1:8137`。

## 限制与上线步骤

- 实际学校 API 连通性、Cloudflare KV 绑定与 Cron 执行、手机日历订阅、Server酱推送尚未线上联调。离线测试和 Edge 窄屏检查不能替代这些验证，也不能代表 Safari / iOS 的表现。
- KV 检测只确认存储绑定存在，不能证明 Cron 已正确配置。页面明确提示手动部署的用户检查定时触发器。
- 浏览器关联写入不是数据库事务；存储持续不可用时恢复旧值也可能失败，页面不会宣称保存成功。
- 现有配置方式仍将令牌保存在浏览器；本轮未改为仅会话保存。启用订阅后凭证保存到自己的 KV；清除浏览器数据不会撤销云端订阅。
- 本轮只做本地实现、验证与版本管理，未推送远端或发布网页，也未更新任何用户的 Worker。线上入口仍是原发布版本。

上线时将本次提交推送到项目远端以更新网页，再更新自己部署的 `worker.js` 并核对根路由能力信息。旧 Worker 继续兼容普通抓取；完整 KV 预检和服务端失败保护需更新 Worker 后生效。

B（统一 Worker 托管）与 C（本地配置向导）仍是后续可选方案，没有混入本轮改动。
